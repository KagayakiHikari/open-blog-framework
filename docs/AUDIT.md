# 安全验证流程

本文件说明项目提供的验证方式，不承诺所有检查始终通过。具体候选的执行记录和敏感证据由维护者保留在仓库外。

1. 在受支持的 Node 安全版本中全新安装精确锁定的依赖，禁止安装脚本。
2. 执行 npm run check 与 npm test。包括真实密码校验、独立 CLI 并发改密／撤销、匿名慢请求、取消及超时、权限、CSRF、Markdown 和上传边界。
3. 执行 npm audit --omit=dev --registry=https://registry.npmjs.org/；单独检查运行时安全公告和原生子组件，不将 npm 零告警视作全部依赖安全。
4. 在无 dist 的干净副本执行 npm run build。release-files.json 精确准入，源码和产物均扫描；构建拒绝隐藏、未列出和链接条目。
5. 执行 npm run scan，覆盖第一方工作树、产物及全部本地 Git 内容对象；常见编码有界解码。扫描仅输出位置、类别、严重性及编码类型，不回显匹配值。
6. 执行 npm run licenses 并人工审核素材、代码权属和实际分发义务。
7. 验证真实入口、初始化、登录及主要页面；部署前另验 HTTPS、可信入口、权限、资源组和备份恢复。

扫描的展开深度、候选数量和字节预算有限，预算耗尽会产生待审结果。人工审查仍需检查未识别编码、身份关联、Git 元数据和依赖二进制。禁止把私人标识加入公共 CI。

规范 GitHub 匿名邮箱仅在 Git 提交作者／提交者及标签创建者的身份字段中列入 publicIdentityReview，仍需核对公开身份；私人标识匹配与其他秘密规则继续阻断。提交消息、源码和 Git 配置中的邮箱不享有此例外。新公开根可通过一次性 Git 进程身份创建，避免写入本地身份配置；私人仓库的配置审核不能替代新根扫描。

CI 定义不等于远程运行结果；Windows 的本地通过不代表 Linux、真实代理或操作系统资源组已验收。最终状态及发布批准由维护者针对固定候选作出。
