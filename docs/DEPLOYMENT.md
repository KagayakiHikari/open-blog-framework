# 独立部署、升级与恢复

本文件描述通用部署要求。**本任务未执行部署。**

项目计划一次性发布，不承诺持续维护或未来安全补丁；以下运行、恢复和更新责任属于部署者，不代表维护者将提供升级版本。

## 配置

| 配置 | 默认 | 限制 |
|---|---|---|
| BLOG_MODE | development | production 必须搭配 HTTPS origin |
| BLOG_ORIGIN | http://localhost:4300 | 只含协议和主机端口；禁止路径、认证信息、查询和片段 |
| BLOG_HOST | 127.0.0.1 | 仅允许回环地址；外网流量由反向代理接入 |
| BLOG_PORT | 4300 | 1–65535 |
| BLOG_DATA_DIR | var | 项目内的专用相对路径；禁止链接、源码目录与外部路径 |
| BLOG_TITLE | 示例小站 | 最多 120 字符，输出转义 |
| BLOG_DESCRIPTION | 记录生活，也分享灵感。 | 最多 300 字符 |
| BLOG_THEME | system | light／dark／system；兼容 paper／night |
| BLOG_DESIGN_FILE | design.json | 项目根目录内显式 JSON 文件名，禁止链接和路径穿越 |

应用不使用远程数据库 URL、JWT Secret 或固定 Session Secret。密码加盐哈希；每个会话使用独立随机令牌和 CSRF token。数据目录只接受框架初始化标记；拒绝接管已有非空陌生目录。

## 生产步骤

1. 在全新目录安装已审核的源码构建。运行 `npm ci --ignore-scripts`，不要省略 optional 依赖。
2. 使用专用低权限系统用户；源码只读，仅授权框架数据目录可写。Windows 的文件模式不替代 NTFS ACL，必须按部署账号设置访问控制。
3. 新配置设置 `BLOG_MODE=production`、`BLOG_ORIGIN=https://example.invalid`，将虚构域名换成自己的域名；应用仍监听回环地址。
4. 在自己的 HTTPS 反向代理中保持配置的 canonical Host。应用不信任客户端 `Forwarded`、`X-Forwarded-For`、`X-Forwarded-Proto`。证书和 TLS 私钥在代理管理范围，禁止放入源码目录。
5. 独立初始化数据库并创建管理员；只使用该实例独立的数据与凭据。
6. 配置唯一受管服务实例、只读根文件系统（可用时）、进程组内存／CPU／任务数量上限和磁盘配额。Node 堆上限不限制 Sharp 原生内存；子进程继承系统资源组约束。避免无界反向代理请求缓冲，按自己的资源预算设置请求体上限及上传超时。
7. 在你自己的测试环境执行 HTTPS Cookie、上传、备份恢复、代理 Host 与共享限流验收，再考虑上线。

服务端通用限制：每个 socket peer 每分钟 600 个动态请求；每 15 分钟 12 次密码验证尝试；每个用户每分钟 60 次写入；最多 2 个同时密码验证、2 个匿名登录读取、4 个已认证读取、1 个图片解码任务。匿名读取总时限 2 秒／空闲 750 毫秒；已认证读取总时限 15 秒／空闲 3 秒。登录读取前对 socket peer 另限每 15 分钟 24 次准入；同一预认证 token 仅一个在途读取。 反向代理下 peer 配额由所有访问者共享；这是有意保守的默认值，可能影响高访问量站点。需要精细代理来源能力时必须单独设计可信代理边界，不能直接信任转发头。

## 运行与更新

显式加载环境：`node --env-file=.env src/server.js`。监督器负责进程重启和外部健康检查，健康接口 `/health` 不包含基础设施信息。`SIGTERM`／`SIGINT` 等待在途请求结束后关闭数据库并释放锁。

`.server.lock` 防止同一数据目录运行两个服务。若非正常退出留下锁，先确认使用这个目录的主进程和媒体子进程**都已退出**，再人工删除该数据目录中的锁文件并重启；禁止仅按 PID 存在与否自动删除锁。不要在服务运行时复制整个应用目录来启动第二实例。

图片临时文件和未入库孤儿在下一次启动时清理，仅清理框架 UUID 文件且至少超过一小时。长期运行时定期检查磁盘；当前不提供自动后台清理调度。媒体为公开资源，删除后引用会失效，不要上传私人文件。

## 备份与回退

由自己的运维流程停止新实例后，备份完整独立数据目录（含 SQLite 关联文件和媒体），并在独立测试实例恢复验证。不要直接复制运行中的 SQLite 主文件并声称得到一致备份。备份包含密码哈希、会话和正文，视作敏感信息加密保存，不能提交 Git。

恢复流程：

1. 停止 Web 实例与媒体任务并确认退出，再复制完整数据目录，包括隐藏标记、SQLite 关联文件和媒体；另行私密保管该实例必要的配置，不复制其他站点配置。
2. 在全新隔离目录安装同一候选，恢复数据到同一相对配置位置，核对文件集合、哈希、数据库完整性和媒体可读性。
3. **保持入口关闭。** 备份会回退口令与认证代际，可能重新带回备份时有效、后来已撤销的会话。对每个恢复账号使用 `node scripts/admin.js revoke USERNAME`（有环境文件时加相同的 `--env-file`）撤销会话；确认账号清单和现行口令，必要时用 `password` 重设。CLI没有账号列表命令，应从自己私密保管的账号记录核对所有账号，不得漏掉编辑账号。
4. 在隔离实例验证公开文章、草稿隔离、归档、登录、图片和旧会话拒绝，再验收权限、HTTPS及备份保存策略，最后开放流量。不要自动删除来源不明的锁文件。

自动回归使用临时目录、真实 SQLite、图片处理与账号 CLI 验证停机复制、恢复和会话撤销；不验证加密介质、跨设备灾难恢复或真实部署权限。实际执行平台与结果以候选验收记录为准。

升级前备份，验证新版本与迁移，再替换源码。当前没有逆向迁移；若未来有破坏性变更，回退源码必须配套恢复兼容备份。对实例的停止、恢复或迁移必须由部署者明确安排。

## 未验证范围

实际 HTTPS／反向代理、Linux 服务资源组、跨平台原生库、NTFS ACL、整机压力与备份恢复均需部署方验收。仓库没有容器镜像或 Docker 构建，容器构建／镜像审计不适用；容器运行未验证。CI 文件存在不表示远程 CI 已执行。
