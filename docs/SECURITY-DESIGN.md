# 安全设计与威胁模型

## 假设

攻击者可完整阅读、搜索、运行和修改公开源码；匿名访问者可控制请求和投稿者提供的 Markdown／图片；可信编辑也可能误操作或尝试越权。源码保密不是控制措施。服务器本机账号和已安装扩展属于可信管理边界；被攻陷的系统管理员、运行时和原生库不由应用沙箱防御。

主要资产是站点内容、密码哈希、会话、媒体和服务可用性。环境、身份和数据必须独立管理；公开源码不能包含私人部署信息。

## 控制

| 威胁 | 实际实现 | 限制 |
|---|---|---|
| SQL 注入 | 用户值均绑定参数；固定查询结构 | 新扩展不得拼接用户 SQL |
| XSS | 模板 HTML 转义；Markdown 渲染后白名单清理；禁 SVG、iframe、脚本及远程图片；CSP | 浏览器安全与原生依赖需要持续更新 |
| CSRF | 登录预认证 Cookie＋token；全部写操作精确 Origin；会话 CSRF；SameSite=Strict | 运维不得添加宽泛跨域配置 |
| 会话劫持 | 256 位随机令牌，数据库仅存哈希；HttpOnly；生产 Secure／__Host-；绝对 8 小时、闲置 30 分钟；认证代际绑定，改密／全会话撤销原子失效 | HTTPS 与数据库访问权限由部署验证 |
| 爆破与资源滥用 | 持久来源配额、写配额、有限哈希并发、分离的匿名／已认证读取预算及空闲／总时限、头与体积限制、单进程锁 | 配额在代理下共享，可能降低可用性；无分布式防护 |
| 越权 | admin／editor；每次内容和媒体写入校验所有权；审计限管理员 | 编辑可以发布自己内容，符合当前模型 |
| SSRF | 不提供抓图、URL 导入、远程数据库或 webhook 功能；运行时无主动网络请求 | 运维安装的扩展会改变这一边界 |
| 路径穿越 | 固定静态资源映射；媒体 UUID 白名单＋数据库存在检查；禁止数据路径越界及符号链接 | 本机特权用户可改变文件；不是本机敌对多租户沙箱 |
| 不安全上传 | 字节签名、格式和像素检查；禁止 SVG／动画；仅公开重新编码的 WebP；随机文件名 | 内容版权与图片视觉隐私由上传者审核 |
| 解码耗尽 | 5 MiB 输入、1600 万像素、2400 像素边长输出、单子进程、12 秒超时、96 MiB JS 堆 | JS 堆不是原生内存硬限；部署必须加进程组限额和磁盘配额 |
| 反序列化 | 仅 JSON／URL 编码表单；禁止危险顶层键；无 eval、YAML 对象构造或任意模块 URL | 已授权代码扩展拥有进程权限 |
| 日志泄露 | 错误日志只含固定事件和 requestId；审计只记录事件与内部对象 ID | 数据目录仍含个人内容和会话元信息，必须保护 |
| 草稿泄露 | 列表、详情、标签、RSS、sitemap 均限制公开状态和发布时间 | 新公开端点需保持一致策略 |
| 供应链 | 精确依赖版本、官方注册表、完整性锁、禁安装脚本、CI 最小权限和固定 action SHA | npm audit 不覆盖所有原生组件或未知漏洞 |

## 交付边界

release-files.json 明确每个交付文件。构建先验证清单和源码，再复制与扫描产物，拒绝隐藏、未列出和链接条目。数据库、环境实值、私钥、日志和审阅证据不得进入源码目录或构建。扫描支持有界常见编码展开，不能替代人工检查。

## 依赖依据

- [Node SQLite 文档](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)：使用标准绑定参数和本地数据库，禁扩展加载。
- [Marked 项目](https://github.com/markedjs/marked)：解析本身不提供 HTML 消毒，本项目额外执行清理。
- [sanitize-html 官方仓库](https://github.com/apostrophecms/apostrophe/tree/main/packages/sanitize-html)：采用显式标签、属性及协议白名单。
- [Sharp 安装说明](https://sharp.pixelplumbing.com/install/)：平台原生依赖需要独立核查和系统资源边界。

这份模型描述实现和限制，不是对不存在漏洞或不可关联的保证。
